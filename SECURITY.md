## Reporting a Vulnerability

We take the security of **suchi** seriously. If you discover a security vulnerability (e.g., sensitive data exposure via history files, daemon privilege issues, or clipboard leakage), please follow these steps:

1. **Do NOT open a public GitHub issue** to report security vulnerabilities.
2. Email your findings directly to the project maintainers or report via GitHub Security Advisories if enabled.
3. Include details to help us reproduce the issue:
   - Type of vulnerability and potential impact.
   - Operating System, Display Server (X11 / xWayland), and dependencies version.
   - Proof of Concept (PoC) or reproduction steps.

### Response & Timeline

- **Acknowledgement:** We aim to acknowledge vulnerability reports within **48 hours**.
- **Updates:** You will receive regular progress updates at least once a week until the issue is resolved.
- **Resolution:** If accepted, a patch will be prepared and released promptly. If declined, we will provide a clear explanation.
